# 维护这个知识库

## 维护的是内容和入口

- 首页只保留少量精选入口，让新读者能迅速选择下一步。
- 专题页说明阅读顺序；完整目录负责覆盖已经收录的条目。
- 每篇正文只维护一份。新增或改变条目时，在同一个 PR 更新相关目录描述。
- 重要结论改变时留下修订说明，并检查引用它的其他文章。

## 内容变多以后怎样整理

当一个专题已经无法在短时间内扫读时，按读者的问题拆成子专题；不要只按日期不断往下堆。

把“入门必读”和“完整索引”分开。过时文章可以标记为待更新，并链接后续修订；保留旧条件与版本记录。

如果重复条目出现，先明确哪篇作为正文来源，再合并有效内容并保留贡献署名。移动已发布条目前检查所有引用，并在旧位置留下迁移说明。

## 讨论区的日常工作

给讨论补充主题标签，帮助新参与者找到相关内容。分类解决活动类型，标签解决主题；不要建立彼此重复的分类树。

长讨论需要导览时，由参与者补一条当前问题、已有材料与未决分歧的总结。只有形成独立可读的内容后才整理成文章，不强求每条讨论都有结论。

## 每次文档 PR 检查什么

1. 标题和摘要是否清楚，是否有合适的主题入口。
2. 内容类型和状态是否准确，是否把计划说成实际结果。
3. 事实来源是否可回查，推断是否超出材料。
4. 相对链接、专题目录和全文导航是否仍然可用。
5. 署名与公开范围是否符合贡献者授权。

首版没有引入自动生成目录或后台服务。以后若目录维护成为重复负担，可再增加仅检查文档与链接的 GitHub Actions；自动检查不能替代内容判断。

## 维护者自己的交接

涉及他人 PR 时，审阅者明确说明需要修正的内容与理由；合并者核对最终修改。涉及社区规范或许可变化时，由仓库所有者作出决定，并向贡献者解释影响。
